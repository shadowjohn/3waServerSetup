# Startup Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement the scoped tasks below. The user has requested direct implementation and `.26` testing; no additional design approval or commit/push is requested.

**Goal:** 讓 root 在現有 Startup 頁編輯、儲存及套用開機 Bash 腳本，另行檢閱立即執行，並可還原／恢復中斷的設定交易。

**Architecture:** 延續 `docs/design.md` 的自有 systemd oneshot 設計。新增獨立 StartupManager，重用 RootManager 的 actor gate、全域鎖、私有備份、原子寫入及 journal；不加入普通六服務的 recipe，也不使用會啟動腳本的 generic service restore。

**Tech Stack:** 現有 Python／Textual、Bash、原生 systemd；不加套件。

**Spec:** `docs/design.md` 開機腳本列；本文件記錄本輪實作的具體選擇。

## Global Constraints

- 實作工作目錄 `D:\mytools\3waServerSetup-root-apply`，保留目前未提交變更；不 commit／push／release。
- 管理目標 Ubuntu 26.04 root；`.26` 實測只執行公開無害 nonce 腳本，不 reboot、不更動 SSH／網路／其他服務設定。
- 完整 config 為 `{schema:1, script:str, enabled:bool, wait_network:bool, timeout_seconds:int}`。Script 最多 65536 UTF-8 bytes、拒 NUL／BOM，CRLF 轉 LF；timeout 1..600，預設 120。
- 預設腳本 `#!/bin/bash\nset -e\n\n# 在這裡加入開機指令；儲存與套用設定不會立即執行。\n`，enabled=False、wait_network=True。
- 固定自有 `threewa-startup.service`；script `/opt/3waServerSetting/config/startup/startup.sh` root 0700，draft 同目錄 `draft.json` root 0600，私有 ownership／transactions 沿用工具目錄。
- systemd `Type=oneshot`、`RemainAfterExit=yes`、`Restart=no`、明確 TimeoutStartSec、KillMode=control-group。User/Group=root、WorkingDirectory=/root、固定 PATH/HOME/locale，移除 shell／loader 注入環境；stdout/stderr 由原生 journal 接管，不寫進工具 JSON 結果。
- `wait_network` 只控制 Wants/After=network-online.target；不是網際網路健康保證。
- Apply 僅 Bash -n、systemd-analyze verify、檔案／daemon-reload／開機 enablement；絕不 start/restart/stop 任意腳本。Restore／補償亦只還原配置和 boot enablement，保留 runtime，已執行腳本的業務副作用不宣稱可還原。
- Run once now 獨立計畫與確認，使用固定 unit 的 start；已 active/exited 時回 NO_CHANGE，避免同一開機重複執行。失敗不自動重試，不自動停止其 background 工作。
- rc.local 顯示存在／執行權限／服務狀態；不讀出或紀錄內容，不自動匯入／修改／建立第二條執行入口。
- 未知同名 unit、drop-in、symlink／外部改動拒絕；journal／普通 log 只記 hash／狀態／私有備份參照，不存 script body。檢閱畫面可以顯示操作者選定腳本。

## Review Focus

1. 補償或 restore 意外重跑／停止使用者腳本：Task 1 明確禁止並釘測試。
2. Apply 在 unit activating／deactivating 時更動腳本：拒絕，避免執行中讀到不同版本。
3. 首次安裝後移除配置、runtime 仍 active/exited：狀態與 ownership 必須可辨識，不能當未知外部 unit 或偷偷重跑。
4. 中斷 run 不能重試造成重複副作用：restore/recover 只核對原生結果並結束 pending。
5. Script 含敏感字串：只進 root 私有檔案／備份與明確 review，不進 ordinary log/status。

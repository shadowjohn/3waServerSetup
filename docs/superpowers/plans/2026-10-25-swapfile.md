# 2026-10-25 Swap 容量與啟用

使用者在防火牆實作期間追加 `/swapfile` 容量調整、啟用及開機持續需求。接續完成防火牆驗收與還原，再進行 swap 原生驗收。

## 決定與範圍

- 開機設定使用 `/etc/fstab`；保留原有註解及其他 mount/swap，不重複加入同一路徑，不建立第二套 rc.local 啟用流程。
- 第一輪管理 `/swapfile` 及已安裝的 `/swap.img`。指定路徑若是未知檔案、symlink、多重 hardlink、非 root 私有或非 swap 格式，一律停止，不能當成可覆寫空檔。
- root / Ubuntu 26.04、本機 ext4，零填充實體檔、0600；未知檔案系統、磁碟空間不足或記憶體餘裕不足時只回報原因。
- 容量 MiB、立即啟用及開機啟用為獨立目標。Save/Load 只保存配方；Apply 顯示實際檔案、現容量、目標容量、swapoff、fstab 差異及回復範圍。
- 新容量先建立同檔案系統的私有候選並格式化；停用原 swap 前重查可用 RAM。保留原 swapfile 至新檔啟用／驗證成功，再清除原檔。不能刪除仍在 `/proc/swaps` 的檔案。
- 對外部變更／半完成交易提供明確回復狀態，不能把 mkswap 或 swapon 失敗報成成功；原有其他 swap 保持原樣。
- 修改後核對 `/proc/swaps`、大小、權限、唯一 fstab 條目與 systemd 重新載入。實測不重開 VM。

## 初始盤點

`.26` 已有 `/swap.img` 3813 MiB，root:root 0600，已啟用且 fstab 只有一筆；使用約 16 KiB。根檔案系統 ext4，剩餘約 9.2 GiB，MemAvailable 約 2.6 GiB。`/swapfile` 與 `/etc/rc.local` 不存在。

原生驗收選擇使用者指定的現有檔管理／遷移／獨立小容量測試；不自行新增第二份正式 4 GiB swap。容量調整、啟停與持續設定分開驗證，結尾核對使用者選定狀態。
